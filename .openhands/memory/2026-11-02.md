# 2026-11-02 — CEF IPC latency + disk-footprint session

Task: "CEF Turbocharge" — cut CEF IPC p95 latency and strip the shipped runtime.

## Result
- IPC latency (CEF, 25s storm): mean ~7.78ms → **0.85ms**, p95 11.6ms → **2.51ms**.
  Electron reference in the same run: mean 0.60ms / p95 2.02ms. So CEF went from
  ~4x worse to within ~0.5ms of Electron; p95 still ~0.5ms above it.
- Shipped footprint 620.0MB → **413.1MB** (libcef.so 426.6→249.0MB after
  `strip --strip-unneeded`; swiftshader/vulkan 35.5→6.3MB by dropping
  libvk_swiftshader.so + vk_swiftshader_icd.json + libvulkan.so.1).
- Idle PSS 359.5 → 358.9MB (roughly flat); peak PSS 439.2MB (still the lightest
  under load of all five runtimes).

## The actual latency fix (src/cef/adrenaline_wakeup.h + src/window.cpp)
Root cause: the engine thread loop did `CefDoMessageLoopWork(); sleep_for(5ms)`,
so every IPC reply waited for the next tick. Fix: block in `poll()` on a
process-wide **eventfd** and pump the instant it is readable. Signal sources:
- JS thread → `PushEngineTask()` → `SignalEngineWakeup()`;
- CEF → `AdrenalineApp::OnScheduleMessagePumpWork()` (any thread) → wake;
- shutdown path → wake so the loop sees `stop`.
`g_cef_active` (set on first window show, cleared in `ForgetClosedWindow`) makes
the pump fire on every wake while a window is up; with no window it throttles to
`kCefIdlePumpPeriod` (100ms) so an idle app doesn't spin. `kCefMaxPumpDelayMs=16`
is only a safety net — proven by a diagnostic: setting it to **50ms changed
nothing** (mean 0.84 / p95 2.49), i.e. dispatch is wake-driven, not timeout-driven.
Also added `--disable-ipc-flooding-protection` (the ~100 pkt/s storm was being
throttled into the p95/p99 tail) and anti-throttling switches
(disable-renderer-backgrounding / -background-timer-throttling /
-backgrounding-occluded-windows) — the last three matter under Xvfb.

## Environment gotchas (costly)
- The container was **reset mid-session**: apt packages (xvfb, xauth, pkg-config,
  cmake, libgtk-3-dev, libwebkit2gtk-4.1-dev) and `node_modules/electron/dist`
  disappeared while workspace files survived. `sudo -n` works for `openhands`.
  Re-provision with:
  `sudo apt-get install -y --no-install-recommends xvfb xauth pkg-config cmake libgtk-3-dev libwebkit2gtk-4.1-dev`
  and `node node_modules/electron/install.js` for the Electron binary.

  `https://cdn.jsdelivr.net/npm/@neutralinojs/lib@6.10.0/dist/neutralino.js`),
  and `unzip` isn't installed (extract with python's zipfile). Provision
  `neu-app/neutralino-linux_x64` + `neu-app/resources/neutralino.js` by hand.
