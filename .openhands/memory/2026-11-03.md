# 2026-11-03 — WebGTK as a third engine; NW.js evicted from the Royal Rumble

## What shipped (branch `feat/webgtk-engine`, commit `80933a4`, not pushed)
- `engine: 'webgtk'` is now a first-class third backend alongside `webview` and
  `cef`. WebGTK = the sister project `github.com/M5Devs/webgtk`, a GTK3/GTK4
  `GtkGLArea` presenting the pruned Blink/V8 core's OSR frames.
- Benchmark Linux roster is exactly: electron, neutralino, adrenaline-webview,
  adrenaline-cef, adrenaline-webgtk. NW.js is gone (registry, launcher,
  `nw-app/`, the `nw` devDependency, and every profiler/report/run reference).

## How the engine actually wires up
- `src/window.cpp`: `#elif ADREN_FEATURE_WEBGTK` branch. `EnsureGtkInitialized()`
  uses `gtk_init_check` (NOT `gtk_init`, which aborts with no display — same trap
  the webview path avoids). Creates `webgtk_view_new(w,h)`, wraps
  `webgtk_view_get_widget()` in a `GtkWindow`, `gtk_container_add`, `show_all`.
  Close = `gtk_widget_destroy` → "destroy" handler unrefs the view + kills the timer.
- **The IPC bridge is the interesting bit.** WebGTK's C ABI has no
  function-binding hook (unlike the webview's `webview_bind`), so there is no
  push channel into the page. Instead a `g_timeout_add(4ms)` tick evaluates a
  script that (a) idempotently installs `window.adrenaline` (survives navigation,
  re-arms itself) and (b) returns one queued `[channel, data]` per call, or
  `null`. The returned JSON is forwarded through the same TSFN envelope the
  webview engine's `__adrenaline_ipc_send` produces, so the JS-side handler is
  shared verbatim. `WebGtkOnIpcResult` ignores anything that isn't a JSON array
  (empty queue, or the mock backend's echo envelope).
- `binding.gyp`: `webgtk_root`/`webgtk_include`/`webgtk_lib` vars (env-overridable
  `WEBGTK_ROOT`/`WEBGTK_INCLUDE_DIR`/`WEBGTK_LIB_DIR`), `-L/-lwebgtk/-Wl,-rpath`.
  Also widened the Linux pkg-config chain to a GTK-only fallback so the webgtk
  build does not require WebKitGTK headers.
- `lib/config-resolver.js`: `SUPPORTED_ENGINES`, and `gypDefines()` now emits
  `ADREN_FEATURE_{CEF,WEBVIEW,WEBGTK}` (exactly one = 1). An unknown engine
  degrades to webview rather than emitting an unbuildable define.
- `scripts/build.js selectEngine(engine, cefAvailable, webgtkAvailable)`.
- `scripts/setup-webgtk.js`: clone at `WEBGTK_REV`, cmake with
  `WEBGTK_ENGINE_DIR` > `WEBGTK_USE_PREBUILT_ENGINE` > mock, install `.so`+headers
  into `vendor/webgtk/`.

## Verification done
- `ADREN_ENGINE=webgtk` clean build, zero warnings under `-Wall -Wextra`;
  `ldd` resolves `libwebgtk.so` from `vendor/webgtk/lib`.
- Default (webview) build: `xvfb-run -a npm test` → all 11 suites pass (exit 0).
  `test_webgtk.js` self-skips when not compiled with webgtk.
- `xvfb-run -a node run.js` (2s) profiles all five runtimes: `5 ok, 0 failed`.
- Regenerated the committed report from evidence. **Important:** the committed
  `profiles-combined.json` had no WebGTK sample, so the canonical report is
  4-way (WebGTK needs the Blink/V8 engine archive, which is not provisioned
  here). `report.js` now drops any runtime that is no longer in the registry
  (`RUNTIMES[r]` guard) so a stale NW.js entry can never render as an empty column.

## Gotchas / environment
- WebGTK mock backend **does not execute JS** (it echoes the script), so the
  renderer IPC round-trip is only meaningful against the real engine
  (`WEBGTK_ENGINE_DIR` set). `test_webgtk.js` is a boot/teardown smoke test in
  mock mode.
- The real engine archive is the HF dataset `M5-Dev/webgtk-chromium-diet`
  (`webgtk_core_v2.tar.gz`, 685 MB) — a pruned Chromium *source* tree, not a
  drop-in prebuilt; it still needs a big-runner `gclient sync` to build.
- Container was reset mid-session: `node_modules/electron/dist` vanished; fixed
  with `node node_modules/electron/install.js` (network is available).
- `vendor/` and `build/` are gitignored; `.bench-artifacts/*.node` too (`*.node`).
